# polysign — сигнальный бот для спортивных рынков Polymarket

Ловит моменты, когда исход матча уже предрешён или матч закончился, а цена
YES на победителя всё ещё ниже $1. Без авто-торговли — только сигналы.

## Сигналы

| Тип | Что значит |
|---|---|
| `[FINAL]` | Игра закончена (по счёту ESPN), ask на победителя < 1. Практически чистый арбитраж |
| `[LIVE-NEARFINAL]` | Матч идёт, но по счёчу и времени исход предрешён (напр. 2:0 на 85-й), ask дешевле оценки p |
| `[ARB]` | Сумма асков всех взаимоисключающих исходов события < 1 (негативный риск) |
| `[BOOK-ONLY]` | Стакан выглядит как «зашедшая ставка»: bid ≥ 0.9 (рынок уже покупает победителя), ask ≤ 0.995, но счёта из ESPN нет — рискованнее: стакан может ошибаться (см. Burnley–West Ham в статистике) |

Формат: `ask 0.978 × $214` — цена лучшего аска и сколько долларов по нему лежит.
Строка котировок под сигналом (`аск: 0.981×$984, 0.985×$180 (+$695 дальше) | bid 0.970×$150`)
— верхние уровни аска до потолка сигнала (сколько ещё можно купить, но дороже)
и лучший бид (для [BOOK-ONLY] бид у 1.0 — фактически единственное «подтверждение»).

## Как пользоваться сигналом (куда нажать и сколько взять)

1. Строка `💰 ЗАБРАТЬ ...` — готовый план: сколько долларов можно забрать
   по всему стакану, пока край не ниже порога, и сколько это принесёт.
   Для одиночных сигналов: `ЗАБРАТЬ $1679 (1706 ш. по 0.984) → профит ~$27 (+1.6%)`
   — купить на $1679, средняя цена выйдет ≈0.984, заработок ≈$27.
   Для [ARB]: `ЗАБРАТЬ 884 наборов ... вложить $875 → гарантированно $884` —
   набор = по 1 шару КАЖДОГО исхода, выплата $1 при любом исходе матча.
2. Ссылка внизу ведёт сразу на нужный рынок (например, Yes-рынок Севильи).
   У [ARB] ссылок несколько — по одной на каждый исход: ордера ставятся в каждый,
   число шаров одинаковое (из строки «набор»).
3. На Polymarket: **Buy** → вписать сумму из плана (в $) → сверить среднюю цену
   с планом → Confirm. Ликвидность уходит быстро: если цена стала хуже плана —
   пересчитай на месте (сколько взял × сколько осталось до $1).
4. Приоритет по надёжности: `[FINAL]` (игра кончена) ≈ `[ARB]` (гарантия
   при любом исходе) → `[LIVE-NEARFINAL]` (исход предрешён по счёту) →
   `[BOOK-ONLY]` (счёта нет, смотри bid: чем ближе к 1.0, тем увереннее рынок).

## Запуск

Нужен Python 3.13+ и одна зависимость для живого стакана (на 3.12 и старее
ESPN-CDN отвечает 403 на запросы urllib — счёт молча пропадает):

```
pip install websocket-client
python bot.py            # цикл по poll_interval_sec (по умолчанию 10с)
python bot.py --once     # один проход (проверка)
python review.py         # статистика: сколько сигналов зашло/не зашло
python review.py --last 100
```

Всё пишется в `signals.log` (JSONL) — его и читает `review.py`.

## Конфиг (config.json)

- `min_edge` — минимальный край `p − ask` (0.004 = 0.4%). Для ручного сбора
  мелких краёв типа 0.1% поставь 0.001–0.002 и `max_ask: 0.9995`
- `min_liquidity_usd` — минимальный объём $ на лучшем аске
- `max_ask` — выше этого аска сигнал не подаётся
- `poll_interval_sec` — период сканирования
- `lookback_hours` / `forward_hours` — окно событий вокруг «сейчас»
- `book_only_sweep` — сигналы без подтверждения счётом (можно выключить)
- `league_map` — [префикс seriesSlug, лига ESPN, спорт, тег Polymarket].
  Именно по тегам лиг Gamma API отдаёт полную выборку (общий тег sports
  теряется). `null` вместо лиги ESPN = счёта по матчам не будет, лига
  работает только по стакану ([BOOK-ONLY]/[ARB]); так живут лиги, которых
  нет в ESPN site API: KBO, NPB, CPBL, K-League и пр.
- `telegram` — `{"token": "...", "chat_id": "..."}` для дублирования в Telegram

Прокси: не нужен — публичные API Polymarket (gamma/clob) доступны откуда угодно.
Если твоя сеть начнёт резать запросы, urllib сам подхватит переменные
окружения `HTTPS_PROXY` / `HTTP_PROXY`.

## Как устроено

1. **Вебсокет CLOB** (`wss://ws-subscriptions-clob.polymarket.com/ws/market`):
   бот подписан на moneyline-токены всех событий в окне и держит живые
   снапшоты стаканов. Изменение (появился/пропал дешёвый аск, вырос размер)
   приходит пушем за миллисекунды — это основной режим. Требует
   `pip install websocket-client`; без библиотеки или при обрыве связи бот
   автоматически уходит на REST-запросы (медленнее, но работает).
2. Gamma API: события по тегам лиг (mlb, efl-championship, la-liga, ...) в окне времени, кэш 2 мин
3. ESPN scoreboard (бесплатный, без ключа): счёт и статус матчей, кэш 40 сек
4. Матчинг названий команд (fuzzy), оценка вероятности исхода:
   - `post` → p = 1.0/0.0 по счёту
   - футбол: лидирует 2+ на 85-й (или 3+ на 70-й) → p ≈ 0.99 и т.п., консервативно
   - баскетбол/хоккей/амер. футбол: пороги «отрыв × секунды до конца»
   - бейсбол in-play не оценивается (нет часов) — только финалы
5. Сигнал, если `p − ask ≥ min_edge` и `$ ≥ min_liquidity_usd`; повторный алерт —
   через кулдаун, при улучшении цены или **при росте ликвидности в 1.5 раза**
   (появились свежие деньги в стакане)
6. [ARB] считается по живым снапшотам по всем событиям окна без ограничений

## Подводные камни внешних API (почему код такой, как есть)

Неочевидные вещи, обнаруженные в бою 2026-08-22. Если что-то здесь изменится
(хост, формат), начинай поиск проблемы с этого списка.

- **Хост ESPN.** `site.api.espn.com` отдаёт 403 с датацентровых IP (раннеры
  GitHub Actions — серверный бот из-за этого неделю не видел счёта и работал
  только в ARB/BOOK-ONLY) и с запросов urllib на Python ≤ 3.12 (другой
  TLS-фингерпринт). Поэтому `sources.py` ходит на `site.web.api.espn.com`
  (хост фронтенда espn.com, те же данные, без блокировок), а Python 3.13
  зафиксирован в README и в воркфлоу.
- **Итоговые цены Gamma.** `/markets?slug=...` перестаёт отдавать закрытые
  рынки — `review.py` читает событие целиком через `/events?slug=...`,
  там цены markets сохраняются навсегда.
- **Футбольные Yes/No.** У футбольных moneyline-рынков outcomes = [Yes, No],
  а не названия команд; сигнал всегда на Yes-токене. Это учитывают
  `analysis.ml_candidates` (берёт toks[0]) и `review.py` (при отсутствии
  команды в outcomes берёт цену Yes).
- **ESPN-география лиг.** KBO/NPB/CPBL в ESPN site API отсутствуют в принципе
  (HTTP 400 на любой вариант слага) — не пытайся вернуть им ESPN-код.

## Честные ограничения

- **Скорость.** ESPN — публичный фид, отстаёт от «полевого» на секунды-десятки
  секунд; в лайве тебя могут опережать боты с платными фидами. Лучшие окна —
  финальные минуты и первые минуты после свистка.
- **Размер.** Показанный $ на аске может быть съеден до твоего клика.
- **Резолюция.** Правила рынка (переносы, дождь, walkover, «доиграть до даты X»)
  читай на странице события: редкий, но полный минус.
- `[BOOK-ONLY]` без счёта — может быть устаревшей ценой, а не дармовой ликвидностью.
- Это не торговый совет; стартуй с малых сумм и копи статистику в `signals.log`.

## Что можно докрутить

- Вебсокет CLOB вместо поллинга стаканов (мгновенная реакция)
- Сверка с Betfair/Pinnacle live вместо/вместе с эвристиками p
- Автоисполнение через py-clob-client (тогда появятся ключи/подпись и KYC-вопросы площадки)
